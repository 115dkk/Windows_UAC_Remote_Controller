# 요구사항 및 구현 계획

상태: 사용자 후속 결정을 반영하고 공통 코어·CI를 구현 중이다. 실기·배포 기능은 아직 입증되지 않았다.

## 사용자 요구사항과 후속 결정

- 데스크톱과 Android 앱을 QR로 연결하고 스마트폰에서 승인/거절한다. 자격 증명형은 휴대폰에서 Windows가 요구하는 항목을 입력하는 방법이 적절하면 지원하고, 무리가 있는 유형은 무시한다(사용자 후속 결정).
- 이미 SYSTEM/커널이 침해된 상태는 위협 모델에서 제외한다(사용자 후속 결정). 정상 OS의 일반 권한 로컬 악성코드, 적대적 네트워크/중계, 미등록 기기 공격은 방어 대상이다.
- Windows는 Rust+Tauri 적합성/unsafe를 먼저 평가한다. Android는 Rust+Tauri, Kotlin은 OS 연결에 사용한다. 직접 작성하는 Android Rust의 unsafe는 원칙적으로 금지한다.
- React/Tauri는 화면과 사용자 입력만 담당한다. 서비스, 네트워크, 요청 상태, 기록 보존은 Rust가 담당한다.
- Secure Desktop 및 Windows 보호 기능을 끄거나 우회하지 않는다.
- 승인 주체는 연결된 스마트폰의 키다. 다른 프로그램에 로컬 승인·실행 인터페이스를 제공하지 않는다.
- 설치 때 한 번 관리자 확인, 최초 QR 등록. 이후 QR 재발급에도 매번 UAC가 필요하다.
- Android 승인 시 OS 인증이 필요하고 거절에는 필요하지 않다. PIN/패턴/비밀번호 없는 기기는 동작을 거부하고 설정으로 안내한다.
- 알림 허용 요일/시간대, 소리/진동/무음. 미설정이면 모든 시간 허용. 비활성 시간의 요청은 Android에서 즉시 폐기하며 나중에 재생하지 않는다.
- 미응답 만료 시 PC 신호를 받고 알림 철회, 기록만 남긴다. 통신 유실 때도 로컬 만료로 오래된 알림이 남지 않게 한다.
- 알림은 ‘UAC 인증 요구’, ‘승인’, ‘거부’, ‘자세하게 확인’처럼 사용자 언어를 쓴다. 내부 이벤트명·에러 코드·플러그인명을 그대로 노출하지 않는다.
- 터미널 요청은 셸과 실행 파일을 먼저, 명령행은 ‘더 보기’로 표시한다. Windows가 보여주는 작업 정보는 기술적이어도 보존한다.
- Windows 관리 화면은 기기 연결/해제, 서비스 중지/재시작/제거, 접속·서비스·장애 기록을 제공한다.
- Windows 11 및 Android 관례를 따른다. 보라색 기본 테마를 피한다. 검증하지 않은 ‘안전/정확’ 홍보 문구를 넣지 않는다.
- GPL-2.0-or-later를 적용한다. 종속 라이선스와 배포 의무는 별도로 점검한다.

권한이 필요한 실기 작업, 외부 계정/푸시/배포 자격 증명, 서명 인증서는 별도 환경이나 사용자 입력이 필요할 수 있다. 없는 것을 있는 것으로 가장하지 않는다.

드라이브 정리는 **프로그래밍·최종 검증을 끝내고 프리릴리즈를 실제로 공개한 뒤** 수행한다. 초안이나 빌드 성공만으로 시작하지 않는다. 현재 디스크
부족을 이유로 먼저 삭제하지 않는다. 실제 절대 경로와 크기, 재생성 가능성,
활성 작업 여부를 확인하고 소스·Git 이력·키/인증서·사용자 데이터·필수 릴리스와
검증 자료를 보존한다. 드라이브나 작업공간 전체를 재귀 삭제하지 않으며,
용도가 불명확한 큰 파일은 자동 삭제하지 않는다. 무엇을 지웠는지, 복구 또는
재생성 방법과 C·E 각각 실제로 확보한 공간을 최상위가 확인해 보고한다.

아래는 정적 설계 감사에서 명확해진 미해결 조건이다. 문서에 요구조건을 추가한 것은 기능 구현·취약점 수정 완료·실기 검증이 아니다. 상세 발견은 [SECURITY_REVIEW.md](SECURITY_REVIEW.md)에 남긴다.

| 게이트 | 구현 전 필요한 결정 | 최상위 에이전트가 이후 확보할 증거 |
| --- | --- | --- |
| 새 UAC와 QR 등록 권한 | 설치 트랜잭션의 단 한 번의 최초 등록, 이후 매 발급의 새 UAC를 해당 PC·도전·스마트폰 키 등록에 결합하는 절차. 일반 Tauri 화면에 비밀을 보여주는 것만으로 권한 경계를 만들지 않음 | 기존 상승 토큰/상승 UI 재사용·같은 사용자 악성 프로세스의 QR 비밀 획득/키 선점·중단·동시 발급·재시작을 다루는 격리 환경 실증. 캡처 제외 플래그를 보안 증명으로 쓰지 않음 |
| 연결된 승인기의 신뢰 루트 | 서비스 소유의 신뢰 목록·키 용도·폐기 상태. 스마트폰 키의 하드웨어/요청별 인증 정책을 인정할 근거와 등록 프로토콜 | UI/중계/저권한 프로세스가 승인키를 바꾸거나 임의 키를 등록하지 못함. 키 소유 증명만을 OS 인증 정책 증명으로 오인하지 않음 |
| 실제 프롬프트와 결정의 결합 | 실제 Windows 요청, 표시 정보, 서명, 최종 동작의 결합 방법. OS 요청 식별/적용 방식은 아직 미정 | 서명 직후 창·세션 교체, HWND/PID 재사용, 동시 요청, 서비스 재시작, 악의적 표시 내용에서 다른 요청이 승인되지 않는 실기 증거 |
| Android 매 요청 인증 | API 30 이상 매 사용 인증과 PIN/패턴/비밀번호 또는 강한 생체 인증을 허용하는 공식 API를 후보로 검토. 최소 버전·AndroidX/플랫폼 인증 경로·키 증명 정책 결정 | PIN만 설정된 기기와 생체 등록 기기 각각의 `CryptoObject` 서명. 이전 잠금 해제·성공 boolean·시간창 키로 대체하지 않음. 잠금 제거/키 무효화/인증 취소/Activity 재생성도 포함 |
| 알림 수신 전 검사와 철회 | 앱 종료 상태에서도 표시 전에 Android의 인증·일정·만료 검사를 거치는 전송/네이티브 진입점. 비활성 시간 폐기를 이후 재전송이 되살리지 않게 하는 규칙 | 비활성 일정·일정 변경·시간대 변경·지연 푸시·중복·취소 유실·절전·강제 종료·재부팅·오래된 알림 버튼을 구분한 실기 결과. 즉시 철회가 보장되지 않는 상태는 그대로 보고 |

Windows의 최종 요청 만료·폐기 검사는 Android의 시계, 알림 표시 여부, 취소 신호 전달 성공과 무관하게 강제한다. SYSTEM/커널 선행 침해는 사용자 결정으로 범위 밖이며 더 이상 미합의 사유로 취급하지 않는다. 자격 증명형의 유형별 입력 가능성은 실제 증거에 따라 지원/무시를 결정한다.

구현 단계에는 서비스/설정/내부 통신의 접근 제어, 입력 길이·작업량 상한, 승인/거절/관리 메시지의 용도 분리, 키 폐기와 재전송 경쟁, 로그의 비밀 제거·용량/기간 상한을 포함한다. 폰 알림의 Intent·딥링크와 Tauri 명령에도 같은 요청 결합을 적용하며 범용 서명·명령 실행 API를 제공하지 않는다. 릴리즈/업데이트 경로는 서비스 실행 코드를 바꿀 수 있는 별도 신뢰 루트로 취급해 서명·배포 권한·다운그레이드 정책을 정해야 한다.

## CI 계약

- Rust: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, Rust Analyzer 진단을 오류·경고 실패 게이트로 운영한다. `cargo check`만으로 Rust Analyzer 검사를 대신했다고 표기하지 않는다.
- PR: `cargo test`와 웹뷰 TypeScript strict/typecheck, ESLint(경고 0), UI 행동 테스트. Windows 전용 코드와 Android 대상도 별도로 컴파일·검사한다.
- main push/merge: 모든 품질 게이트 후 Windows/Android 배포 빌드와 자동 릴리즈. 권한 있는 산출물 게시에는 PR 코드나 PR 산출물을 무검증으로 재사용하지 않는다.
- Actions는 공식 릴리즈를 확인해 checkout 7.0.1/setup-node 7.0.0의 커밋 SHA로 고정했고 Node 24 런타임을 사용한다. PR/main 품질 워크플로와 로컬 검증을 작성·수행했다. 실제 GitHub 실행 및 main 자동 릴리즈는 아직 남아 있다. 상세 내용은 [CI.md](CI.md)와 [PROGRESS.md](PROGRESS.md)에 있다.
- `pull_request_target`에서 신뢰하지 않은 PR 코드를 실행하지 않는다. 기본 토큰은 읽기 전용, 릴리즈 job만 최소 쓰기 권한. 서명 키를 PR에 공개하지 않는다.
- 테스트 실패를 `continue-on-error`, `|| true`, 경고 무시, 플랫폼 작업 제외로 감추지 않는다. CI 검사명은 병합 필수 조건으로 설정할 항목을 문서화한다. 실제 GitHub 저장소 설정 변경은 별도 확인한다.
- 버전/태그·릴리즈 중복 실행·동시 main push·서명 실패·SBOM/라이선스·소스 배포 정책까지 명시한다.

## 에이전트 운영 계약

- 최상위 에이전트만 빌드·테스트·lint·실행 검증을 한다. 하위 에이전트의 결과는 검증 전 구현/정적 검토 결과로만 취급한다.
- 각 하위 에이전트에 수정 파일 소유권을 지정하고 타인의 변경을 되돌리지 못하게 한다.
- 보안 감사관 한 명이 완성된 결과물의 취약점을 정적으로 점검·수정한다. 실행 테스트는 하지 않는다.
- 구현 완료 후 **새** 에이전트를 생성해 사용자가 지정한 `improve-codebase-architecture` 스킬로 전체를 리팩터링한다. 지금은 공통 코어와 읽기 전용 관찰만 구현되어 전체 프로그램의 후속 리팩터링을 수행한 것으로 간주하지 않는다.
- 리팩터링 스킬의 후보 선택·승인은 사용자가 최상위 에이전트에 위임했다. 리팩터링 에이전트는 후보 보고서를 먼저 제출하고 최상위의 검토를 기다린다. 최상위가 요구사항·보안 불변조건·변경 범위·위험을 검토해 승인한 방안과 조건을 **같은 에이전트**에 다시 전달한다. 후속 설계 질문도 최상위가 판단하며 밤중 사용자 승인 대기를 만들지 않는다. 승인되지 않은 방안은 수정 보고를 요구한다. 이 위임은 기능 축소·보안 약화·검증 생략의 승인이 아니다.
- 다른 하위 에이전트는 자식 생성 금지. 리팩터링 에이전트만 구조 파악 후 작업 자식을 만들 수 있고, 그 자식은 재위임 금지. 모든 실행 검증은 여전히 최상위가 담당한다.
- `runpod_*` 에이전트를 사용할 때는 같은 `task_name`으로 정확한 평문 과제를 `controller.py stage-task`에 먼저 전달한다. 실패하면 생성하지 않는다. 현재 RunPod 에이전트는 사용하지 않았다.
- 최신 사용자 지시는 남은 마지막 초기화권1회를 잔여 한도3% 이하에서 사용하도록 승인한다. 사용 전에 실제 잔여량과 이용 가능한 초기화권을 확인하고 소비 결과를 기록한다. 이전의 최대2회 허용을 새로운 추가 사용권으로 해석하지 않는다.
